Outcomes record observable evidence that something changed. Unlike actions (which track effort), outcomes track results. Outcomes attach to intentions or project Topics. They can be recorded on both **Active** and **Completed** intentions, allowing retrospective evidence to be added after an intention is finished. Outcomes can also be classified with a category and extended with user-defined custom properties in the same way as intentions; see [`rei custom-property`](/docs/commands/custom-property) for how to define and assign properties.

## Project evidence and replay

```bash
rei outcome record "Released 5.0.0" --project shinzui-rei --id outcome_01kh9280qte2hvc4h8jp0tg5b3 --at 2026-07-15T12:00:00Z --json
rei outcome list --project shinzui-rei --json
rei project show shinzui-rei --no-mori
```

Project recording requires a server cohort with project-outcome writes enabled.
The first successful call prints `changed: true`; a completed retry with the same
ID and project prints `changed: false`. The first description, performer, home,
and original `--at` time are immutable. A different subject using that ID is a
conflict. New writes require an active, project-classified Topic.

If the call is interrupted, retry with the same ID and canonical Topic ID. The
server recovers its saved recording and scope Edge before acknowledging success;
a pending retry uses the original payload even after archival or classification
changes. Keep the printed ID or supply `--id` before sending. The saved local
recovery draft also contains the request. The canonical receipt is available at
`GET /api/v2/outcomes/{id}/project-receipt`, independently of query visibility.

Lists and portfolio samples update asynchronously. Project lists use effective
scope, including outcomes inherited through scoped intentions, with each outcome
shown once. Unfiltered `rei outcome list` includes both subjects. Project show
includes at most five recent outcomes with their dates; its count can be larger.
Recency uses the original fact time, so replaying an old release today does not
make it recent. Generic custom properties support both subjects; category
commands require an intention-owned outcome.

## Subcommands

### record

Record an outcome for an intention or a project.

```bash
rei outcome record [description] [options]
```

**Arguments:**
- `[description]` — Description of the outcome (optional, can be provided via stdin)

**Options:**
- `-i, --intention <id>` — Intention ID (optional if fzf is available)
- `--project <project>` — Project key, canonical `topic_…` ID, or stored external reference; mutually exclusive with `--intention`
- `--id <outcome_id>` — Caller-chosen ID for project recording; reuse it to recover or replay
- `--json` — Print one JSON acknowledgment with `changed`, `outcomeId`, and the subject ID
- `-t, --at <time>` — When the outcome was achieved (optional, defaults to now)
- `--actor <actor>` — Actor performing this action (overrides global `--actor`)

> **FZF Support:** If neither `--project` nor `-i` is provided and [fzf](https://github.com/junegunn/fzf) is installed, an interactive picker will let you select from active intentions.

> **Completed Intentions:** You can record outcomes on completed intentions too. This is useful when results or evidence are discovered after an intention has been marked complete.

**Relative Time:**

The `--at` option accepts human-readable relative time expressions:
- Keywords: `now`, `today`, `yesterday`, `tomorrow`
- Natural expressions: `2 hours ago`, `30 minutes ago`, `1 day ago`
- Short forms: `-2h`, `-30m`, `-1d`, `2h`, `30m`
- ISO 8601: `2024-01-15T14:30:00Z`, `2024-01-15T14:30:00+09:00`

**Examples:**

```bash
# Record an outcome with explicit intention
rei outcome record -i intention_01h455vb4pex "Deployed to production successfully"

# Let fzf pick the intention interactively
rei outcome record "Deployed to production successfully"

# Record via stdin
echo "All tests passing, 95% coverage" | rei outcome record -i intention_01h455vb4pex

# Record an outcome that happened 2 hours ago
rei outcome record "Feature approved by client" --at "2 hours ago"

# Record yesterday's outcome
rei outcome record -i intention_01abc... "Milestone completed" -t yesterday
```

### set-category

Assign a category to an outcome. Categories help classify and organize outcomes for reporting and filtering, and they can auto-initialize category-scoped state machine properties on the outcome.

```bash
rei outcome set-category OUTCOME_ID CATEGORY_SLUG
```

**Arguments:**
- `OUTCOME_ID` — Outcome ID to categorize
- `CATEGORY_SLUG` — Category slug (e.g., 'work', 'personal/health')

**Examples:**

```bash
# Set category on an outcome
rei outcome set-category outcome_01h455vb4pex work/milestone

# Use a nested category slug
rei outcome set-category outcome_01h455vb4pex personal/health
```

**Notes:**
- Any state machine custom property scoped to the category is auto-initialized on the outcome when the category is assigned.

### clear-category

Remove the category from an outcome.

```bash
rei outcome clear-category OUTCOME_ID
```

**Arguments:**
- `OUTCOME_ID` — Outcome ID

**Examples:**

```bash
# Clear the category from an outcome
rei outcome clear-category outcome_01h455vb4pex
```

### set-property

Set a custom property on an outcome.

```bash
rei outcome set-property OUTCOME_ID KEY VALUE [--force]
```

**Arguments:**
- `OUTCOME_ID` — Outcome ID
- `KEY` — Property key
- `VALUE` — Property value (validated against property definition)

**Options:**
- `--force` — Bypass state machine transition rules (still blocked from terminal states)
- `--at <time>` — When the change actually happened (e.g. `"2 hours ago"`, `-1h`, `2024-01-15T14:30:00Z`). Defaults to now.

**Examples:**

```bash
# Set a property on an outcome
rei outcome set-property outcome_01h455vb4pex impact high

# Set a numeric property
rei outcome set-property outcome_01h455vb4pex confidence 4

# Skip intermediate states on a state machine property
rei outcome set-property outcome_01h455vb4pex review-state accepted --force

# Backdate a state transition
rei outcome set-property outcome_01h455vb4pex review-state accepted --at "yesterday 3pm"
```

**Notes:**
- The property must be defined first using `rei custom-property create`
- The property must be configured to apply to outcomes (`--entity-type outcome`)
- Values are validated against the property definition (enum options, numeric ranges, etc.)
- `--force` only affects state machine properties — it bypasses transition rules but cannot leave terminal states.
- `--at` records the **effective time** of the change. `rei custom-property metrics` uses this for cycle-time and lead-time math.

### clear-property

Remove a custom property from an outcome.

```bash
rei outcome clear-property OUTCOME_ID KEY
```

**Arguments:**
- `OUTCOME_ID` — Outcome ID
- `KEY` — Property key to clear

**Examples:**

```bash
# Clear a property from an outcome
rei outcome clear-property outcome_01h455vb4pex impact
```

### append-property

Append one or more values to a multi-value custom property (path-list, label-set, tag-set). Idempotent.

```bash
rei outcome append-property OUTCOME_ID KEY VALUE [VALUE...]
```

Each `VALUE` is a separate shell argument; commas are preserved literally. See [`rei intention append-property`](/docs/commands/intention) for the full description.

### remove-property-value

Remove one or more values from a multi-value custom property. Idempotent.

```bash
rei outcome remove-property-value OUTCOME_ID KEY VALUE [VALUE...]
```

## Actions vs Outcomes

| Actions | Outcomes |
|---------|----------|
| What you did | What changed |
| Effort | Results |
| "Wrote for 30 minutes" | "Published blog post" |
| Process | Evidence |

Both are valuable:
- Actions track your investment of time and energy
- Outcomes track the results of that investment

## Viewing Outcomes

Outcomes appear in:
- `rei intention show --full` — When viewing an intention
- `rei intention timeline` — Chronological history
- Weekly reviews

## Mori property writes

The set/append commands accept `--allow-unresolved`, and set/append/remove accept `--json`. Mori lists use a JSON array for set and separate URI arguments for append/remove. JSON mode requires an explicit subject and returns the stored reference evidence. See [Mori artifact references](/docs/commands/custom-property#mori-artifact-references) for restrictions, statuses, reverse lookup, rechecks, and the default-off reader-first rollout.
