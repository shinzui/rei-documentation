`rei subscription` has been removed.

Event-stream processing now runs through the kiroku-backed keiro worker:

```bash
rei worker kiroku
```

Run the PGMQ queue workers separately when you need asynchronous jobs such as workspace git sync, reminder triggering, dormancy checks, or agent work:

```bash
rei worker all
```

## Migration

| Previous command | Current command |
|------------------|-----------------|
| `rei subscription run all` | `rei worker kiroku` |
| `rei subscription run <read-model>` | `rei worker kiroku` |
| `rei subscription run git-commit` | `rei worker kiroku` plus `rei worker all` |
| `rei subscription run agent-schedule-event-reactor` | `rei worker kiroku` |

Most read models update inline on command writes. The worker is still required for event-triggered reactors, asynchronous projections, delayed work, and queue handoffs.

## Inspecting subscriptions

To check that subscriptions are keeping up, use the Kiroku operator command:

```bash
rei kiroku subscriptions status
# or against a running worker's metrics endpoint:
rei kiroku subscriptions status --remote-url http://localhost:9091
```

See [`rei kiroku`](/docs/commands/kiroku) for details.
