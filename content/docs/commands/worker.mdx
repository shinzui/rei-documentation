Run background job workers for event-stream and queue-based processing.

## Overview

The worker command runs background processors. `rei worker kiroku` hosts the keiro reactive layer that maintains read models, runs reactors, and enqueues async work. Queue workers consume PGMQ jobs for tasks like git commits, dormancy evaluation, and reminder triggering.

## Subcommands

### all

Run all queue workers in a single process.

```bash
rei worker all
```

This is the recommended way to run workers in production. It starts:
- `workspace-git-sync` — Commits note files to git with batching and deduplication
- `reminder-trigger` — Triggers due reminders (triggered by pg_cron)
- `reflection-scheduler` — Creates successor reflections
- `agent-work` — Evaluates agent schedules and executes scheduled agent work
- an in-process periodic scheduler that feeds the periodic queue checks

### kiroku

Run the keiro reactive layer against the kiroku event store.

```bash
rei worker kiroku
```

This keeps read models current, runs event-triggered reactors, and schedules queue work such as workspace git sync jobs. Run it alongside `rei worker all` in production.

The kiroku worker also routes due Kioku distillation timers for agent memory. Kioku schedules these timers when agent sessions and turns are recorded. Rei's timer dispatcher recognizes `kioku-l1-extract`, `kioku-l2-scene`, and `kioku-l3-persona` rows so they are not claimed as unknown no-ops.

The kiroku worker also starts a **kiroku-metrics HTTP server** that exposes live subscription status (the `/subscriptions` endpoint). Query it from another process with [`rei kiroku subscriptions status --remote-url`](/docs/commands/kiroku).

| Variable | Description | Default |
|----------|-------------|---------|
| `REI_KIROKU_METRICS_PORT` | Port for the kiroku-metrics server. Set to a non-negative integer to choose a port (`0` picks a free OS-assigned port), or one of `disabled`, `off`, `false`, `no` to turn the server off entirely. | `9091` |

```bash
# Default: metrics server on port 9091
rei worker kiroku

# Custom port
REI_KIROKU_METRICS_PORT=9200 rei worker kiroku

# Disable the metrics server
REI_KIROKU_METRICS_PORT=disabled rei worker kiroku
```

When a router or process manager halts for good, the worker writes one error line for it, inside the reactor's trace span:

```text
[worker] router <name> halted at global position <n>: <reason>
```

A halted reactor makes no further progress until it is fixed and the worker is restarted, and `rei kiroku subscriptions status` cannot yet show a halted state, so watch the worker log for this line.

### checked-mapping-process-audit

Run only the Note-to-Task process manager, for an isolated checked-mapping audit on a restored database. It is an operator tool for release rehearsals, not a production worker.

```bash
rei worker checked-mapping-process-audit
```

### Kioku Memory Embeddings

Kioku owns memory embedding storage and backfill. Rei hosts Kioku's distillation timers in `rei worker kiroku`, but embedding backfill and continuous embedding work should be run with the Kioku worker companion until Rei grows a first-class embedding worker subcommand.

Use the same PostgreSQL connection string as Rei:

```bash
PG_CONNECTION_STRING="$REI_PG_CONNECTION_STRING" kioku worker --backfill
```

For continuous embedding work, run:

```bash
PG_CONNECTION_STRING="$REI_PG_CONNECTION_STRING" kioku worker
```

If pgvector is unavailable, Kioku reports that recall will run in FTS-only mode and still runs the timer worker path.

### git-sync

Run only the git sync worker.

```bash
rei worker git-sync
```

Useful for testing or when you only need git commit functionality.

## Graceful Shutdown

`worker all` and `worker git-sync` stop accepting new queue work, wait for active handlers to drain, and then exit. The default drain budget is 30 seconds. Override it with a positive integer number of seconds:

```bash
REI_WORKER_DRAIN_TIMEOUT_SECONDS=45 rei worker all
```

A clean stop exits successfully and reports how many processors drained. If the budget expires, Rei prints each processor's state, in-flight count, and received/processed/failed counters, then exits nonzero. Unacknowledged PGMQ messages remain eligible for redelivery after their visibility timeout.

Configure the outer service manager's termination grace period to exceed Rei's drain budget. With the 30-second default, use at least 45 seconds. For systemd:

```ini
TimeoutStopSec=45s
```

## Usage

Workers should be run as background processes:

```bash
# Host event-sourced read models and reactors
rei worker kiroku &

# Run queue workers
rei worker all &
```

Or with a process manager like systemd:

```ini
[Unit]
Description=Rei Worker
After=network.target

[Service]
ExecStart=/path/to/rei worker kiroku
Restart=always
TimeoutStopSec=45s

[Install]
WantedBy=multi-user.target
```

## How It Works

1. **Kiroku worker** listens to event streams, updates read models, and runs reactors
2. **Reactors** enqueue delayed or asynchronous work to PGMQ queues when needed
3. **Queue workers** poll the queues and process messages
4. Messages are batched with configurable delays for efficiency

For example, the git sync flow:
- The keiro git sync reactor sees a `NoteCreated` event
- It enqueues a message to the `workspace_git_sync` queue with a short delay
- The `git-sync` worker picks up the message and commits the file

## Requirements

- Database backend (PostgreSQL with PGMQ extension)
- PGMQ extension must be installed
- For periodic checks: pg_cron extension must be installed and configured
