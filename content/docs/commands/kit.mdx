Manage distributable skills and subagents from the rei-kit registry, for both **Claude Code** and **Codex**. Skills and agents can be installed, updated, and removed independently of Rei binary releases.

Every install writes **both** provider layouts so the content is discoverable whichever provider an interactive session runs under (selected by `REI_LLM_PROVIDER`):

- **Claude Code** reads skills/agents from Rei's agent base directory (`.claude/skills/`, `.claude/agents/`), which Rei passes to the session.
- **Codex** discovers skills from `.agents/skills/` and custom agents from `.codex/agents/*.toml` in its own native roots (the working tree for project scope, `$HOME` for user scope). Kit agent Markdown is wrapped into a Codex custom-agent TOML (`developer_instructions`).

## Subcommands

### list

Fetch (or update) the registry and show all available skills and agents with their descriptions.

```bash
rei kit list
```

### install

Install a skill or agent.

```bash
rei kit install <name> [--project]
```

**Arguments:**
- `<name>` — Name of the skill or agent to install (required)

**Options:**
- `--project` — Install to project scope (`.rei/agents/`) instead of user scope

Re-installing overwrites existing files with the latest version.

**Examples:**

```bash
# Install to user scope (available in all projects)
rei kit install rei-bootstrap

# Install to project scope (only this project)
rei kit install rei-bootstrap --project
```

### update

Pull the latest registry and re-install installed items.

```bash
rei kit update [<name>]
```

**Arguments:**
- `[name]` — Name of a specific item to update (optional; default: all installed items)

### uninstall

Remove an installed skill or agent.

```bash
rei kit uninstall <name> [--project]
```

**Arguments:**
- `<name>` — Name of the skill or agent to uninstall (required)

**Options:**
- `--project` — Uninstall from project scope instead of user scope

### status

Show all installed items with their type (skill or agent), scope (user or project), and the providers they cover (`claude`, `codex`, or `claude,codex`).

```bash
rei kit status
```

`uninstall` removes every provider copy for the item+scope, and `update` repairs a missing provider copy (e.g. if only the Claude copy is present, the Codex copy is restored).

## Scopes and provider layouts

Kit supports two installation scopes, each writing both provider layouts:

**User scope** (default):
- Claude Code: `~/.config/rei/agents/.claude/skills/<name>/` and `.../.claude/agents/<name>.md`
- Codex: `~/.agents/skills/<name>/` (skills) and `~/.codex/agents/<name>.toml` (agents)
- Available in every project

**Project scope** (`--project` flag):
- Claude Code: `.rei/agents/.claude/skills/<name>/` and `.rei/agents/.claude/agents/<name>.md`
- Codex: `.agents/skills/<name>/` (skills) and `.codex/agents/<name>.toml` (agents), at the working-tree root
- Available only in the current project directory
- Can be version-controlled by committing the `.rei/agents/`, `.agents/`, and `.codex/` directories

Claude Code sessions are given both scopes automatically when started by Rei; Codex discovers project-scope content from the working tree and user-scope content from `$HOME`.

## Offline Use

If a git pull fails (no network), kit falls back to the cached repository at `~/.cache/rei/kit/` and prints a warning. The cache is disposable — delete it and it will be re-cloned on next use.
