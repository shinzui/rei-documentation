Operator commands for the Kiroku event store that backs Rei. These are low-level inspection tools for diagnosing the keiro reactive layer, not part of the day-to-day coaching workflow.

## `rei kiroku` or `rei ops`?

Both report on subscriptions, but they read different things, and only one of them is useful from a plain shell.

| Question | Command |
|----------|---------|
| Where is each subscription durably checkpointed, and how far behind the log head? | [`rei ops stream subscriptions`](/docs/commands/ops) |
| What phase is a **running** worker's subscription in right now? | `rei kiroku subscriptions status --remote-url ...` |

`rei kiroku subscriptions status` **without** `--remote-url` inspects the current process's own in-memory registry. A CLI invocation registers no subscriptions, so it prints an empty table — that is expected, and it does not mean Rei has no subscriptions. Use `rei ops stream subscriptions` for that, or point this command at a running worker.

## Subcommands

### subscriptions status

List live subscription phases and global cursor positions.

```bash
rei kiroku subscriptions status
```

Use this to confirm that the keiro worker is keeping up with the event stream: each subscription reports its current phase (e.g. catching up vs. live) and how far its cursor has advanced through the global event log.

**Options:**

| Option | Description | Default |
|--------|-------------|---------|
| `--format table\|json` | Render as a human-readable table or script-friendly JSON | `table` |
| `--remote-url URL` | Query a running worker's kiroku-metrics `/subscriptions` endpoint instead of this process's local registry | (local registry) |

**Querying a running worker.** By default, `subscriptions status` inspects the KirokuStore registry *of the current process*. To inspect a live `rei worker kiroku` process, point it at that worker's metrics endpoint:

```bash
# The worker exposes the kiroku-metrics server on port 9091 by default
rei kiroku subscriptions status --remote-url http://localhost:9091

# Script-friendly output
rei kiroku subscriptions status --remote-url http://localhost:9091 --format json
```

See [`rei worker`](/docs/commands/worker) for how to enable, move, or disable the metrics server on the worker side (`REI_KIROKU_METRICS_PORT`).

## Requirements

Kiroku operator commands require the Kiroku store runner. Rei opens it automatically when the database connection is configured; if it is unavailable the command prints:

```
Error: Kiroku operator commands require the Kiroku store runner
```
