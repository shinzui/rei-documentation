Enqueue reminder, reflection and agent-schedule checks, and inspect recent execution history.

`enqueue` and `history` use `REI_API_URL` and `REI_API_TOKEN`. They need no caller database settings. `status` is an operator command that reads the database's pg_cron configuration.

## Enqueue

```bash
rei periodic-check enqueue reminder
rei periodic-check enqueue reflection
rei periodic-check enqueue agent-schedule
rei periodic-check enqueue all
```

The command prints a request identity to stderr before sending. A successful answer records queue admission, followed by the familiar enqueue message; workers process that work separately. If only some targets are accepted, the command prints each target's state and exits with an infrastructure failure. It never automatically repeats a write.

After an uncertain response, inspect the printed request identity through the authenticated `GET /api/v2/periodic-checks/requests/{id}` API or Haskell client. A stopped worker leaves accepted work pending. Do not infer execution completion from admission.

## History

```bash
rei periodic-check history
```

Shows the newest 20 check executions, their start time, source, status and processed-item count. Failures expose the server's safe diagnostic rather than private stored error details. Queue admission alone creates no execution-history row.

## Operator status

```bash
rei periodic-check status
```

Reads pg_cron job names, schedules and active state using the operator database runtime. Installed schedules and worker configuration remain server responsibilities.
