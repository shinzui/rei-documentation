`rei system` has been removed.

Its only subcommand, `rei system evaluate-dormancy`, was a manual trigger for the legacy
MessageDB dormancy evaluator. Dormancy marking is now owned by a durable keiro timer, so
there is nothing to trigger by hand — run the worker instead:

```bash
rei worker kiroku
```

## Migration

| Previous command | Current behaviour |
|------------------|-------------------|
| `rei system evaluate-dormancy` | Automatic, via the dormancy timer in `rei worker kiroku` |
| `rei system evaluate-dormancy -t DAYS` | Set `intentions.dormancy_threshold_days` in your config file |

## Dormancy today

An intention is marked dormant after `intentions.dormancy_threshold_days` without activity
(default 10), and a revisit reminder is scheduled `intentions.dormancy_reminder_days` later
(default 21). Dormancy is hierarchy-aware: a parent with active children is not dormant.

The reminder is cancelled automatically when the intention awakens, and completed when the
intention reaches a terminal state.

- Configuration: [Configuration](/docs/configuration#default-values)
- Reminders: [`rei reminder`](/docs/commands/reminder)
- Worker: [`rei worker`](/docs/commands/worker)
- Inspecting dormant intentions: `rei intention list --dormant`
